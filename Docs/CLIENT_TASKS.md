# API 연결을 위한 클라이언트 작업 목록

작성일: 2026-09-22. `[ ]` 항목은 **미구현 작업**이다. 이 문서 작성으로 구현 완료를 의미하지 않는다.
API 계약은 [API_IMPLEMENTATION.md](API_IMPLEMENTATION.md), 현재 연결 지점은
[API_INTEGRATION.md](../Assets/Scripts/Lobby/API_INTEGRATION.md)를 참고한다.

## 현재 상태

- 에디터 생성 로비, 프로필·소셜 4탭·인벤토리·캐릭터 선택 UI와 슬라이드가 존재한다.
- 플레이어 데이터는 placeholder. 서버 전송기/응답기, 인증, 프로필·인벤토리 전체 바인딩은 없다.
- 캐릭터는 원화 4종 미리보기와 `BindOwnership` / `ApplyConfirmedCharacter` 연결 지점이 있다.
- 하트는 창 열기/새로고침 트리거, 개별 작업 로그, 메모리 중복 방지와 오래된 응답 차단만 있다.
- TCP 매칭과 ConnectionTest는 존재하지만 로비 전투 버튼은 아직 로그만 출력한다.
- 솔로 디펜스 씬에 이동·조준·사격·웨이브·사망/비콘 파괴와 결과 화면이 구현되어 있다.
- 공통 싱글톤이 `dedicated_battle` / `solo_defense` 모드별 게임 정보와 이벤트를 추적한다.
- 디펜스 종료 시 실제 게임 로그 저장/보상 요청을 전송하며, API 미구현 시 각각 실패를 표시한다.
- 데디케이티드 전투 플레이·서버 사망 이벤트·프로필 성장 상태 저장 연동은 아직 없다.

## P0 — 계약과 공통 기반

### C01. 서버와 미결정 계약 확정

- [ ] API 명세 8절의 경험치, 부활, 종료/이탈, 하트 정책을 합의한다.
- [ ] HTTPS API와 기존 TCP 역할, DTO 필드·enum·오류 code·revision·멱등 키를 확정한다.
- [ ] 인증 계정과 TCP PlayerId, battleId, participationId의 연결 계약을 확정한다.
- [ ] 모호한 데이터에 임의의 0/성공/소유 값을 넣지 않도록 공통 규칙을 합의한다.

완료 기준: 서버·클라이언트가 같은 계약을 사용하며 미결정 보상 규칙이 코드 상수가 되지 않는다.

### C02. 인증·통신 수명과 HTTP 전송 계층

- [ ] 제안 위치 `Assets/Scripts/Services/`: API 설정, DTO, HTTP client, 인증 세션, 서비스 인터페이스를 추가한다.
- [ ] UnityWebRequest 등 HTTP 구현을 선택하고 취소·타임아웃·오류 파싱·토큰 만료를 처리한다.
- [ ] 재시도는 조회와 멱등 mutation을 구분한다. 결과 불명 mutation은 같은 키로 복구한다.
- [ ] HTTP와 TCP 콜백을 Unity 메인 스레드로 전달한다. 파괴/비활성 UI를 뒤늦게 갱신하지 않는다.
- [ ] 로그에 토큰이나 인증 정보를 남기지 않는다.
- [ ] 계정 변경/로그아웃 시 진행 요청, 캐시, 캐릭터 상태, 하트 작업 기록을 모두 초기화한다.
- [ ] 앱 수명 관리 오브젝트도 Editor 메뉴 또는 사전 구성 씬/프리팹으로 배치한다.

완료 기준: 응답 지연·취소·401·타임아웃을 구분하고 이전 계정의 응답이 새 계정 UI에 적용되지 않는다.

### C03. 서버 상태 저장과 UI 상태 분리

- [ ] 프로필/장비/캐릭터/하트 상태 저장소와 리소스 revision 비교를 추가한다.
- [ ] `Unknown`, `Loading`, `Ready`, `Empty`, `Error`, mutation 진행 상태를 구분한다.
- [ ] 목록마다 검색어/페이지/새로고침 generation을 두어 오래된 응답을 무시한다.
- [ ] 클라이언트 request revision과 서버 리소스 revision을 구분한다.
- [ ] 재시도·오류 안내·빈 목록 UI를 빌더에서 미리 생성한다.

완료 기준: 오래된 결과가 최신 상태를 덮지 않고 미확인과 정상 0/빈 목록이 다르게 표시된다.

## P1 — 현재 로비 API 연결

### C04. 프로필·로비 요약

대상: `LobbyController`, `LobbySceneBuilder`.

- [ ] `GET /me` 결과를 이름, 레벨, 경험치, 경기/승패, 현재 캐릭터 표시에 바인딩한다.
- [ ] 현재 빌더에만 존재하는 Text들을 명시적 view 참조/컴포넌트로 묶는다.
- [ ] 0경기, 최대 레벨, 재접속, 정산 후 프로필 갱신을 처리한다.

완료 기준: 성공 응답으로만 placeholder를 해제하고 로비·프로필·결과 화면이 같은 성장 상태를 사용한다.

### C05. 친구·검색·추천·요청

대상: `LobbyController.RefreshSocial/SearchFriends`, `LobbySocialSlot`.

- [ ] 친구/검색/추천 조회를 실제 서비스에 연결한다. 추천 새로고침은 첫 페이지를 다시 조회한다.
- [ ] 서버 `relationship`과 `canRequestFriend`로 ADD FRIEND 상태를 결정한다.
- [ ] 요청 진행 중 중복 클릭을 막고 성공 후 서버의 요청 상태를 표시한다.
- [ ] 받은/보낸 친구 요청 목록과 수락·거절 UI를 **Editor 빌더로 추가**한다. 현재 이 UI는 없다.
- [ ] 목록 페이지 크기에 맞게 슬롯 수를 Editor에서 늘리거나 페이지 이동 UI를 추가한다.
  현재는 친구/추천/하트 각 3행, 검색 2행이라 실제 응답을 조용히 잘라 표시하면 안 된다.
- [ ] 유저 이름 등 서버 문자열을 리치 텍스트로 해석하지 않고 길이/레이아웃을 처리한다.

완료 기준: 검색 없이 추천 대상에게 요청할 수 있고, refresh·검색어 변경 후 이전 대상에게 잘못 전송하지 않는다.

### C06. 하트 일괄 자동 송수신

대상: `LobbyHeartAutomation`, `LobbyController.OpenFriends/RefreshSocial`, 하트 탭.

- [ ] 권장 `POST /me/hearts/sync` 계약 채택 여부를 확정한다.
- [ ] 창 열기/새로고침을 sync 한 요청으로 연결하고 진행 중 중복 트리거를 합친다.
- [ ] **일괄 sync 채택 시 기존 ApplyEligibility의 개별 receive/send 로그 경로를 실제 API로 연결하지 않는다.**
- [ ] 현재 HashSet의 '로그를 출력했음'을 서버 성공으로 간주하지 않는다.
- [ ] 같은 작업의 재시도 키, 진행/성공/실패 상태, 최신 balance/revision을 관리한다.
- [ ] 창을 닫은 뒤 서버에서 완료되더라도 미완료로 단정하지 않는다. 재진입 시 조회로 복구한다.
- [ ] 하트 이력은 읽기 전용으로 바인딩한다. 수동 보내기/받기 버튼을 다시 추가하지 않는다.
- [ ] 서버 결과가 없는 동안 잔액을 증가/감소시키거나 완료 문구를 표시하지 않는다.

완료 기준: 화면의 고정 슬롯 수와 관계없이 모든 가능 대상이 처리되고, 연속 refresh·재접속으로 중복 전송/수령되지 않는다.

### C07. 캐릭터 변경

대상: `LobbyCharacterPicker`.

- [ ] 캐릭터 카탈로그·소유·현재 선택을 조회해 서버 characterId ↔ artKey를 연결한다.
- [ ] 초기 현재 캐릭터는 소유 정보 바인딩 후 `ApplyConfirmedCharacter`로 반영한다.
- [ ] RequestChange를 PUT에 연결하고 진행 중 적용/선택 정책, 실패 안내, revision 충돌을 처리한다.
- [ ] 빠른 선택 변경 중 먼저 보낸 요청의 늦은 응답이 최신 선택을 덮지 않도록 한다.
- [ ] API 카탈로그가 로컬 4종보다 많거나 artKey가 없을 때 대체 표시/지원 정책을 마련한다.
- [ ] 표시명은 서버/catalog 데이터로 바인딩한다. 현재 `CHARACTER 01` 같은 원화 번호는 영구 이름이 아니다.

완료 기준: 미리보기는 적용이 아니며 서버 성공 후에만 로비·프로필의 캐릭터가 함께 변경된다.

### C08. 인벤토리·장비

대상: `LobbySceneBuilder.BuildInventory`, 신규 inventory view/service.

- [ ] 고정 12개 placeholder 슬롯을 서버 아이템 인스턴스에 재바인딩한다.
- [ ] 현재 `InspectItem`은 미연결 안내만 표시하므로 선택 상세/슬롯/수량 UI를 추가한다.
- [ ] 장착/해제 버튼과 진행·실패 상태를 Editor에서 생성한다.
- [ ] 로비 장비 요약과 인벤토리 장착 상태를 같은 revision으로 갱신한다.
- [ ] 빈 인벤토리, 미지원 artKey, 12개 초과 페이지를 처리한다.

완료 기준: 서버 소유 아이템만 장착할 수 있고 실패 시 기존 장비를 유지한다.

## P2 — 전투 입장·사망·경험치 결과

### C09. 테스트 통신에서 로비 전투 입장으로 연결

대상: `MatchmakingClient`, `NetworkClient`, `Development/PacketHandler`, `LobbyController.EnterBattle`.

- [ ] `MatchmakingClient.HandleConnected()`의 연결 즉시 RequestMatch 동작을 분리한다.
- [ ] 개발용 ConnectionTest와 실제 로비가 공유할 인증된 연결/이벤트 라우터를 만든다.
- [ ] 전투 입장 버튼에서만 RequestMatch하고 대기·취소·오류 상태를 표시한다.
- [ ] 기존 Ready/Waiting/InSession과 로비 버튼 상태를 연결한다. 중복 요청을 막는다.
- [ ] MatchFound와 신규 전투 시작 정보에서 battleId/participationId를 저장하고 사전 제작 전투 씬으로 이동한다.
- [ ] 기존 5초 매칭 요청 타임아웃·연결 종료 규칙을 확인하고 로비 HTTP 요청 정책과 혼동하지 않는다.

완료 기준: 로비 연결만으로 매칭되지 않으며, 서버 성사 확인 전에는 전투로 이동하지 않는다.

### C10. 전투 이벤트와 참여 수명

- [ ] 서버와 합의한 protobuf 원본을 수정하고 `Tools/Generate-Protocol.ps1`로 생성한다.
  `Generated/Matchmaking.cs`를 수동 편집하지 않는다.
- [ ] 서버 사망 이벤트를 처리하고 해당 참여를 사망/정산 대기로 전환한다.
- [ ] 네트워크 예외나 연결 종료를 사망으로 임의 판정하지 않는다.
- [ ] 부활/재입장 정책에 맞춰 participation/life 식별자를 관리한다.
- [ ] 로컬 킬 카운터는 연출용으로만 사용하고 확정 킬/경험치 지급 입력으로 제출하지 않는다.

완료 기준: 서버가 확정한 자기 참여 사망만 정산 대기를 유발하며 다른 참여 이벤트와 혼동하지 않는다.

### C11. 전투 보상 결과 UI와 정산 수신

- [ ] Editor 메뉴로 사망/정산 대기/정산 완료/오류 패널을 생성한다.
- [ ] 확정 킬 수, 획득 경험치, 이전/이후 레벨, 레벨 내 경험치, 다음 레벨 필요량을 표시한다.
- [ ] BattleRewardSettled 또는 결과 조회 응답을 공통 결과 모델에 연결한다.
- [ ] settlementId로 결과 연출 중복을 막는다. 경험치를 클라이언트에서 추가 지급하지 않는다.
- [ ] profileRevision으로 최신 프로필만 반영한다. 오래된 정산 결과는 기록으로 보여도 현재 레벨을 되돌리지 않는다.
- [ ] pending 중 임의 0 경험치/레벨업을 표시하지 않는다. 완료 응답 후에만 결과 연출을 한다.
- [ ] 다중 레벨업, 최대 레벨, 정상 0경험치, 정산 실패를 구분한다.

완료 기준: 사망 후 경험치가 한 번 반영되고 결과 화면과 로비 수치가 서버와 일치한다.

### C12. 정산 복구와 로비 복귀

- [ ] 진행 참여 ID를 계정 범위에서 복구 가능하게 관리한다.
- [ ] 이벤트 유실·재접속 시 참여 결과를 조회한다. 참여 ID를 잃으면 결과 목록으로 복구한다.
- [ ] pending 조회 간격·상한과 취소 처리를 구현한다. 무한 고속 polling을 하지 않는다.
- [ ] 결과가 늦어도 서버 정산을 취소한 것으로 취급하지 않는다. 로비 복귀 후에도 갱신할 수 있게 한다.
- [ ] 서버/계정 변경 시 다른 참여의 결과와 UI를 섞지 않는다.

완료 기준: 정산 전후 어느 시점에 연결이 끊겨도 중복 지급 없이 최종 결과를 확인할 수 있다.

## P3 — 통합 검증·릴리스 정리

- [ ] 조회/변경 오류, 인증 만료, 계정 전환, 취소, 느린 응답·역순 응답 검증.
- [ ] 친구 요청 경합, 하트 sync 중복/재시도/다중 클라이언트 검증.
- [ ] 소유권 오류, 캐릭터 변경 경합, 장비 revision 충돌 검증.
- [ ] 중복 사망·중복 정산 이벤트, 0킬, 레벨 경계, 다중 레벨업, 최대 레벨 검증.
- [ ] 정산 트랜잭션 이후 알림 유실, 재접속 및 pending 복구 검증.
- [ ] 기존 TCP 프레임/매칭 검증을 유지하고 신규 이벤트 code 및 최대 payload 검증 추가.
- [ ] Editor 생성 씬의 참조, 페이지 슬롯, 해상도별 레이아웃과 키보드/마우스 입력 검증.
- [ ] 로그 스텁의 운영 전송 경로 잔존 여부, API 환경 설정, 크레딧과 사용 가이드 갱신 확인.

## 권장 진행 순서

1. C01 계약 확정 → C02 인증/전송 → C03 상태 관리.
2. C04 프로필 → C05 소셜 → C06 자동 하트 → C07 캐릭터 → C08 장비.
3. 서버의 전투/정산 계약과 함께 C09~C12 구현.
4. P3 통합 검증. 경험치 정책과 정산 고유 키가 확정되기 전에는 보상 기능을 완료 처리하지 않는다.
