# 로비 API 연결 지점

이 문서는 **현재 로그 전용 UI 코드의 연결 지점**을 설명합니다.
전체 서버 계약 제안은 [API 구현 명세](../../../Docs/API_IMPLEMENTATION.md),
진행할 작업은 [클라이언트 작업 목록](../../../Docs/CLIENT_TASKS.md)을 참고하세요.
권장 일괄 `POST /me/hearts/sync`를 채택하면 아래 개별 하트 로그 경로를 실제 전송으로
연결하지 않고 sync 결과 바인딩으로 교체해야 합니다.

현재 코드는 UI placeholder와 로그 전용입니다. 아래 문자열은 로그용 작업 이름이며,
확정된 서버 엔드포인트/프로토콜이 아닙니다. 네트워크 전송기나 응답기는 추가하지 않았습니다.

| 영역 | 로그 작업 | 서버 데이터 도착 전 |
| --- | --- | --- |
| 프로필 | `profile.get / self` | 이름/레벨/경기/승패/승률 `--` |
| 친구 목록 | `friends.list` | 친구 수/플레이어/접속 상태 `--`, 하트는 자동 처리 상태만 표시 |
| 검색 | `friends.search` | 결과 미확인, 친구 요청 비활성; 공백 입력은 요청 로그 없음 |
| 추천 | `friends.suggestions / recently-online` | 최근 접속 유저 미확인, 친구 요청 비활성 |
| 친구 요청 | `friends.request.send targetUserId=...` | 추천/검색에 같은 요청 동작 사용 |
| 자동 하트 동기화 | `hearts.sync` | 친구 창 열기/새로고침 시 가능 여부 조회 의도만 로그 |
| 하트함 | `hearts.balance / history` | 잔액/보낸 사람/시각 `--`, 읽기 전용 |
| 하트 전송 | `hearts.send targetUserId=...` | 서버의 전송 가능 여부 필요 |
| 하트 수령 | `hearts.receive targetUserId=... operationId=...` | 서버의 수령 가능 여부와 수령 항목 ID 필요 |
| 인벤토리 | `inventory.get / self` | 장착 장비/아이템/개수 `--`; 슬롯 선택 비활성 |
| 캐릭터 | `characters.catalog / ownership / current` | 서버 ID/소유/현재 캐릭터 미확인 |
| 캐릭터 변경 | `characters.change characterId=...` | 소유 캐릭터가 아니거나 이미 현재 캐릭터면 적용 비활성 |
| 전투 | `battle.enter` | 로그만 출력, 매칭/씬 전환 없음 |

## 소셜 바인딩

`LobbySocialSlot.Bind(userId, displayName, detailText, canAct, heartReceiptId)`는
에디터에서 만들어 둔 행을 채우는 UI 메서드입니다. 정상 서버 결과를 검증한 서비스 어댑터가
메인 스레드에서 호출할 연결 지점이며, 현재 앱에서 호출해 가짜 데이터를 채우는 코드는 없습니다.

- `SendFriendRequest`: 검색 결과와 최근 접속 추천 목록에서 동일하게 대상에게 친구 요청을 보냅니다.
  다른 친구에게 유저를 소개하거나 추천 메시지를 보내는 기능이 아닙니다.
- `SendHeart` / `ReceiveHeart` 행은 읽기 전용입니다. 수동 하트 버튼은 없고 `AUTO / --`를 표시합니다.
  행의 `Bind`나 `RequestAction`은 하트를 전송/수령하지 않습니다.
- `Clear()`는 ID, 수령 항목 ID, 가능 여부, 표시 내용을 함께 초기화합니다.
- 새로고침은 선택된 탭의 행을 Clear한 뒤 해당 조회 로그를 출력합니다. 검색 탭은 현재 검색어를 사용합니다.
- 작업 버튼 핸들러에서도 ID/가능 여부를 다시 검사합니다. 로그 뒤 잔액이나 관계를 변경하지 않습니다.

현재 행은 에디터에 고정 생성됩니다(친구/추천/하트 각각 3개, 검색 2개). 실제 서비스의
페이지 크기에 맞춰 에디터에서 슬롯을 늘리거나 기존 슬롯을 재바인딩하는 페이지 처리를
추가할 수 있습니다. 런타임에 행을 Instantiate하지 않습니다.

## 자동 하트 송수신

`LobbyHeartAutomation`은 친구 창을 열거나 소셜 창을 새로고침할 때 `hearts.sync` 로그를
출력합니다. 하트 탭을 따로 열 필요가 없습니다. API 미연결 상태에서는 결과나 잔액을
추정하지 않고, 자동으로 보냈다/받았다는 완료 표시도 하지 않습니다.

추후 서비스는 조회 시작 시 `CurrentRevision`을 보관하고, 검증된 전체 가능 목록을
`ApplyEligibility(requestRevision, inbox, friends)`에 넘깁니다. 이 메서드는 응답 파서가 아닌
자동 처리 연결 지점입니다. 수령 가능한 항목을 먼저, 전송 가능한 친구를 다음으로 처리합니다.
화면의 고정 행 3개나 현재 활성 탭에 제한되지 않습니다.

각 항목에는 서버가 확인한 `userId`, `allowed`, `operationId`가 필요합니다.
수령은 고유 수령 항목 ID, 전송은 해당 친구의 **전송 가능 회차에 고유한 안정적인 키**를
사용해야 합니다. 단순 현재 시각이나 새로고침 번호로 키를 만들면 안 됩니다.
현재 구현은 작업 로그만 한 번 출력하며, 잔액·수령 이력·성공 상태를 바꾸지 않습니다.

- 같은 작업 키는 중복 응답, 탭 전환, 새로고침, 창 닫기/다시 열기에도 재처리하지 않습니다.
- 새 전송 가능 회차의 새 키는 처리할 수 있습니다. 불가능한 항목은 키를 소모하지 않습니다.
- 새로고침 이전 응답과 창을 닫은 후 늦게 온 응답은 revision으로 무시합니다.
- 계정 변경 시 `ResetForAccount()`로 창 상태와 작업 키를 초기화합니다.
- 실제 전송기를 연결할 때는 로그 전용 중복 기록을 요청 중/성공/실패 상태로 확장하고,
  같은 서버 멱등 키로 실패 재시도를 처리해야 합니다. 현재 로그는 성공을 의미하지 않습니다.

## 캐릭터 바인딩

`char-1`~`char-4`는 **로컬 원화 키**로 서버 캐릭터 ID가 아닙니다.
`LobbyCharacterPicker.BindOwnership(artKey, serverCharacterId, isOwned)`로 실제 서버 ID를
연결하기 전에는 모든 소유 상태가 미확인이고 적용 버튼도 비활성입니다.

`Preview(index)`는 선택 표시만 바꿉니다. `RequestChange()`도 현재는 로그만 출력하며
활성 캐릭터, 소유 정보, 프로필 그림을 변경하지 않습니다.
서버의 성공 결과를 검증한 후에만 `ApplyConfirmedCharacter(serverCharacterId)`를 호출하면
미리 생성한 로비/프로필 그림의 활성 상태를 바꿉니다. 알 수 없는 ID나 미소유 캐릭터는 거절합니다.
실패/거절 응답에서는 기존 캐릭터를 유지해야 합니다.
로그아웃/계정 변경 시 `ResetServerState()`로 원화 미리보기와 미확인 상태로 되돌립니다.

실제 API 연결 시 인증, 자기 자신/이미 친구/요청 중인 유저 제외, 전송 한도/쿨다운,
중복 요청 방지, 요청 중 UI 잠금, 오류/재시도, 새로고침·검색의 오래된 응답 무시,
캐릭터 변경 응답 순서 검증은 서비스에서 구현해야 합니다. 지금의 로그를 성공 응답으로
취급하거나 로컬 원화/슬롯 수로 소유권이나 잔액을 추정하지 마세요.
