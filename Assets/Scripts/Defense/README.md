# 솔로 디펜스 프로토타입

`Assets/Scenes/SoloDefense.unity`를 열고 Play → 전투 시작으로 시작한다.
재생성 메뉴는 **ZPD → Defense → Create Solo Defense Scene**이다.
기존 씬을 덮어쓰지 않고 고유 이름으로 저장한다. 카메라, 아레나, 캐릭터,
적 48개, 플레이어 탄환 128개, 적 투사체 48개, 골드 더미 96개, 피드백 스프라이트 96개, 진입 예고 2개,
적 상태 표식, 효과음 AudioSource 2개, UI 및 버튼 이벤트는 모두 에디터에서 배치된다.
런타임에는 배치된 풀을 활성화하고 이동할 뿐 씬/게임 오브젝트를 생성하지 않는다.

## 플레이

게임 내 설명과 조작 안내는 **ESC → 일시정지 메뉴의 `?` 버튼**에서만 볼 수 있다.
안내 창에서 ESC/돌아가기를 누르면 일시정지 메뉴, 다시 ESC/계속하기를 누르면 전투로 돌아간다.
시작 화면과 전투 HUD에는 상시 설명을 표시하지 않는다. 체력·골드·상점 상태와 물품 성능 표시는 유지한다.
안내 중 전투와 상점 시간은 계속 정지 상태다. 전체 디펜스 UI에 Noto Sans KR Regular를 적용했으며
폰트 원본 라이선스는 `Assets/ThirdParty/NotoSansKR/LICENSE.txt`에 동봉했다.

- WASD / 방향키: 이동. 마우스: 조준. 왼쪽 버튼 유지: 연사.
- Space: 대시(2초 재사용 대기). Esc: 일시정지/복귀. 포커스를 잃어도 정지한다.
- 1/2/3: 강화 카드 선택. 4: 체력 회복 구매. 5: 비콘 수리 구매. M: 효과음 음소거.
- 웨이브 종료 후 카드 1장을 무료로 선택한다. 선택 전에는 준비 시간이 멈추고, 선택 후 8초간 준비한다. Enter 또는 버튼으로 다음 웨이브를 즉시 예고한다.
- 플레이어 사망 또는 비콘 파괴로 종료한다. 결과 화면에서 요청을 재시도하거나 새 게임을 시작한다.

## 들판·골드·보급 상점

피난민이 떠난 마을의 마지막 신호석을 지키는 **The Last Signal** 들판이다.
캐릭터 원본을 참조해 굵은 검은 선과 단순한 면 색상으로 배경을 제작했다.
격자와 아레나 테두리를 제거하고 카메라 종횡비에 맞춰 배경을 균일 확대하므로 여백 없이 덮는다.
가장자리의 울타리·돌은 배경 장식이며 충돌 장애물이 아니다.

- 적 처치 위치에 8골드가 드롭된다. 가까이 가면 끌려오며 반경 1.4 안에서 회수한다.
- 풀 96개가 모두 사용 중이면 가까운 기존 더미에 합쳐 골드가 소실되지 않는다.
- 매 웨이브 종료 후 준비 구간에만 보급이 열린다. 전투 중에는 상점이 전장을 가리지 않는다.
- 1웨이브는 적 9마리, 총 드롭 72G다. 골드는 체력 회복과 비콘 수리에 사용한다.
- 일시정지/포커스 상실 중에는 전투와 상점 시계가 모두 멈춘다. 종료된 상점에서는 구매할 수 없다.
- 체력 최대/골드 부족 시 불필요한 지출을 막는다. 비콘 수리는 보급당 1회만 가능하다.
- 골드와 카드 강화는 **해당 판에서만 유효**하며 재시작 시 초기화된다. 계정 재화/인벤토리를 변경하지 않는다.

| 물품 | 가격 | 효과 |
| --- | --- | --- |
| 기본 발사기 | 기본 지급 | 0.24초 간격, 1발, 피해 1 |
| 다중 발사 카드 | 웨이브당 1장 무료 선택 | 발사체 +1, 최대 7발 |
| 강화 탄환 카드 | 동일 | 탄환당 피해 +1, 최대 50 |
| 속사 훈련 카드 | 동일 | 기본 발사 속도 +15% 누적, 최대 13회(2.95배) |
| 체력 회복 | 15G | +35, 최대 100 |
| 비콘 수리 | 25G | +15, 최대 100, 보급당 1회 |

무기 구매와 교체는 제거했다. 세 카드의 강화는 서로 독립적으로 누적된다.
발사 간격은 `0.24 / (1 + 속사 선택 횟수 × 0.15)`이며, 다중 탄환은 4도 간격으로 퍼진다.
카드는 최대 강화에 도달하면 선택할 수 없고, 모든 카드가 최대면 준비 시간이 바로 흐른다.
발사할 탄 수만큼 풀에 자리가 있을 때만 한 번의 발사를 완성한다. 최대 강화에서도 풀 128개로 충분하다.
탄환 명중의 약한 넉백·0.12초 경직은 같은 적에게 한 발사당 한 번 적용되며 공격 준비를 취소한다.
위협 단계는 `1 + (웨이브-1)/2의 정수 몫`이며 체력·이동속도·피해량은 생성 시 단계로 고정한다.
추격병(청록 막대)은 가까운 플레이어를 추적하고, 비콘 공격병(주황 마름모)은 비콘을 향한다.
2웨이브부터 비콘 공격병과 사격병을 섞고, 3웨이브부터 두 방향 진입을 사용한다.
사격병(보라 세로 막대)은 플레이어를 향해 접근한 뒤 6.2 거리에서 조준한다.
근접 공격은 0.6초, 원거리 공격은 0.9초간 준비한다. 조준선은 준비 시작 때 고정되며 탄환은 유도되지 않는다.
적 투사체는 분홍색이며 속도 5.5, 수명 4.5초, 피해 `6 + 생성 단계`, 발사 후 재사용 대기는 1.7초다.
플레이어나 비콘 중 먼저 닿는 대상에 피해를 준다. 대시 무적 중 플레이어에 닿으면 피해 없이 소멸한다.
준비 중인 사격병을 맞히면 조준이 취소된다. 웨이브 종료 시 잔여 적 투사체를 제거해 안전하게 카드를 고른다.
적의 분리 이동과 분산된 비콘 접근 위치로 겹침을 줄인다. 사격병·비콘 공격병과 피격한 적은 체력 바를 표시한다.

웨이브마다 1.5초간 진입 위치를 예고한다. 상하 경로는 비콘과 가까우므로 생성 간격을 늘린다.
다음 웨이브는 적 수가 3씩 늘며 최대 40이다. `DefenseGame.waveRules`에서 초기 마릿수,
증가량, 준비·예고 시간, 병종·양방향 도입 시점과 생성 간격을 편집한다.
가격·수리량·회복량은 `DefenseSupplies`에서 조절한다. HUD는 생존 적/미출현 적, 비콘 체력,
대시 재사용 상태를 보여준다. 준비·예고·경직·공격 준비 시간은 일시정지 시 멈춘다.

`DefenseSoundBuilder`는 에디터에서 원본 파형을 22,050Hz mono PCM WAV 11종으로 저장한다.
런타임은 저장된 클립을 재생한다. 동시 명중음은 제한하고 볼륨은 `DefenseAudio.volume`에서 조절한다.
출처와 이미지 제작 프롬프트는 `Assets/ThirdParty/CREDITS.md`, `Assets/ArtSource/Defense/IMAGEGEN.md`에 기록했다.

## 전투 피드백

`DefenseFeedback`는 전투 판정과 분리된 시각 반응을 처리한다.

- 사격: 짧은 총구 섬광, 무기 반동과 복귀, 조준점 크기 반응. 다중 발사는 더 강한 반응을 준다.
- 명중: 적의 순간적인 색 변화와 눌림·복원, 작은 충돌 파편.
- 처치: 더 넓은 황금색 파편과 짧은 화면 진동.
- 피격: 플레이어/비콘의 붉은 반응과 파편, 비콘의 크기 반응.
- 대시: 청록색 시작 파편과 이동 흔적. 골드 회수: 짧은 금색 반짝임.

`DefenseGame.screenShake`로 화면 진동 강도를 조절한다. 기본 0.65, 0이면 끈다.
조준 좌표는 카메라 진동 오프셋을 제거해 사격 방향이 흔들리지 않게 한다.
피드백은 피해량·이동 판정·전투 시간·적 출현 난수에 영향을 주지 않는다.
일시정지 시 카메라를 원위치로 돌리고 효과를 정지한다. 재시작과 종료 시 효과를 초기화한다.

기존 씬과 씬 생성기 모두 비활성 SpriteRenderer 96개를 미리 배치한다.
풀이 가득 차면 오래된 효과를 재사용하며 런타임에 GameObject를 생성하지 않는다.
캐릭터와 적의 원래 색·크기는 시작 시 캐시하고 피드백 종료 후 복원한다.

## 설계 패턴과 확장 지점

| 패턴 | 구현 | 역할 |
| --- | --- | --- |
| Strategy | `IEnemyTargetStrategy`, `IEnemyAttackStrategy` | 대상 선정과 근접/원거리 공격을 분리한다. `DefenseGame`은 전략의 사거리·준비 시간과 실행 결과를 사용한다. |
| Factory / Flyweight | `DefenseEnemyFactory` | 병종별 대상·공격 전략과 이동·체력·표식을 조합한다. 전략은 상태 없이 공유하고 조준·쿨다운은 각 `EnemySlot`에 보관한다. |
| Command | `IDefenseUpgradeCommand`, `DefenseUpgradeCatalog` | 카드의 적용 가능 여부·설명·스탯 변경을 캡슐화한다. UI는 명령을 선택하며 한 장 제한은 `DefenseSupplies`가 관리한다. |
| Object Pool | `DefenseEnemyProjectilePool` | 적 투사체 48칸을 획득·이동·반환한다. 풀이 꽉 차면 실패를 반환하고 공격 전략은 자리가 날 때 발사를 재시도한다. |

카드 수치와 상한은 `DefenseUpgrades.cs`, 병종 조합은 `DefenseEnemyStrategies.cs`, 투사체의
이동·연속 충돌 판정은 `DefenseEnemyProjectilePool.cs`, 웨이브 구성은 `DefenseWaveRules.cs`에서 수정한다.
플레이어 탄환도 같은 선분-원 충돌 판정을 사용하며 피해량은 발사 시점의 스탯으로 고정한다.

## 씬 갱신 및 검증

기존 씬을 열어 `ZPD > Defense > Upgrade Open Defense Scene`을 실행하면 새 표식·상점·게이지를
추가한다. 저장은 에디터에서 수행한다. 이미 갱신한 씬에는 중복으로 추가하지 않는다.
저장된 `SoloDefense.unity`에도 변경 사항이 반영되어 있다.

`Tools/DefenseValidation/Run.ps1`은 프로젝트를 `Temp/SoloDefenseValidation`에 복사하고
설치된 패키지를 재사용해 별도 Unity 배치 프로세스로 실행한다. `validation-result.txt`와
`validation.log`에서 결과를 확인한다. 원본 에디터 세션은 조작하지 않는다.
실제 씬의 Play 모드에서 카드 중복 방지·누적·상한·초기화, 선택 시간 보장, 적의 조준 고정,
투사체 충돌·대시 회피·풀 고갈 및 재사용, 보급·수리, 일시정지와 카메라 복원을 검증한다.
`-Capture` 옵션은 D3D11로 카드·전투 화면도 `cards.png`, `combat.png`에 렌더링한다.

추가 카드 효과·병종·보스와 5웨이브 완주 모드는 후속 검토 항목이다.
현재판은 기존 무한 방어와 종료·보상 API 계약을 유지한다.

## 두 게임 모드와 기록

`Zpd.Gameplay.GameMode`는 `DedicatedBattle` → `dedicated_battle`,
`SoloDefense` → `solo_defense` 두 모드다. 현재 플레이 가능한 신규 구현은 솔로 디펜스다.
데디케이티드 모드의 실제 전투 연결은 기존 TCP 매칭 이후 추가 구현이 필요하다.

씬에 배치된 `GameSessionTracker`는 중복을 제거하는 `DontDestroyOnLoad` 싱글톤이다.
자동 생성하지 않으므로 향후 전투 진입 씬에도 에디터로 배치해야 한다.
`Begin` → `Advance` 및 이벤트 기록 → `Finish` 순서로 사용한다.
데디케이티드 모드의 `Begin`에는 서버 발급 `battleId`, `participationId`가 필수다.

기록: runId, 모드, 시작/종료 UTC, 클라이언트 버전, 실제 시뮬레이션 시간,
종료 사유, 킬·웨이브·발사·명중·피해량·남은 체력, 골드 획득/사용량, 최종 무기 및 이벤트.
위치는 약 1초 간격으로 기록한다. 상세 이벤트는 2,048개와 종료 이벤트 1개까지이며
초과분은 `droppedLogEvents`로 집계한다. 요약 카운터는 계속 증가한다.
완전한 리플레이가 아닌 분석용 클라이언트 관측 로그다.

`Finish`는 한 번만 확정하고 JSON 복사본을 반환한다. 이후 재시도는 같은 기록과 ID를 사용한다.
종료 로그는 `Application.persistentDataPath/pending-game-results/{runId}.json`에도 보관하며,
서버 저장 확인을 받은 해당 파일만 제거한다. 디스크 쓰기 실패는 경고 로그로 남긴다.
앱 정상 종료 중 진행 게임도 로컬 저장한다. 강제 종료 복구, 누적 파일 자동 업로드,
보상 요청 자체의 디스크 복구는 아직 구현하지 않았다.

## 실제 API 요청과 실패 UI

씬의 `Solo Defense` 오브젝트 → `DefenseRewardClient.apiBaseUrl`을 설정한다.
기본값은 서비스가 없는 `https://127.0.0.1:18080`이다. 현재 인증 토큰은 붙이지 않는다.
5초 타임아웃의 실제 HTTP 요청을 보내므로 서버가 없으면 실패 화면이 표시된다.
임의 성공이나 로컬 경험치 지급은 하지 않는다.

| 목적 | 요청 | Idempotency-Key |
| --- | --- | --- |
| 게임 플레이 로그 저장 | `POST /api/v1/me/game-results` | `{runId}:game-result` |
| 솔로 보상 요청(프로토타입) | `POST /api/v1/prototype/defense-runs/{runId}/rewards` | `{runId}` |

로그 저장 본문은 `GameRunSnapshot` 전체다. 서버 저장 확인 형식:

```json
{"status":"stored","runId":"요청과 같은 ID","resultId":"서버 저장 ID"}
```

보상 요청 본문은 `runId`, `mode`, `reason`, `claimedKills`, `reachedWave`, `survivalSeconds`다.
확정 보상 응답 형식:

```json
{"status":"settled","runId":"요청과 같은 ID","settlementId":"서버 정산 ID","earnedExperience":10}
```

위 경험치는 형식 예시이며 계산식을 의미하지 않는다. 경험치 정책은 서버에서 정한다.
두 요청은 독립적이다. `RETRY FAILED REQUESTS`는 미확정 요청만 재전송하며
이미 성공한 요청은 건너뛴다. 새 게임은 이전 요청을 취소하고 새 runId를 발급한다.
미확정 로그 백업은 유지한다. 응답 불명 타임아웃 후 중복 처리는 서버의 멱등성으로 막아야 한다.

클라이언트의 `source=client_unverified` 로그 및 `claimedKills`를 보상 증명으로 신뢰하면 안 된다.
운영 솔로 보상에는 서버 발급 세션/검증 정책이 필요하다. 데디케이티드 전투는 전투 서버의
사망·킬 확정 결과로 정산한다. UI에 표시된 성공도 현재는 로컬 프로필을 수정하지 않는다.
